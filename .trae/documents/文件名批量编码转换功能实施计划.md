# 文件名/文件夹名批量编码转换功能实施计划

## Context

参考 `D:\TabTaskExplorer\references\convmv-2.0`（Perl 工具 convmv），为 TabTaskExplorer 新增「文件名、文件夹名的批量编码管理与转换」功能。用户已拍板三点：

1. **界面形态**：独立「编码转换」对话框（工具栏新入口，与批量改名并列，不合并）
2. **递归范围**：支持递归开关（对应 convmv `-r`），默认不勾选，勾选后深度遍历选中目录全部后代
3. **编码范围**：尽量全、跟随 convmv，双向转换

convmv 核心语义（探索结论）：
- `-f` 源编码、`-t` 目标编码、`-r` 递归；只转换文件名/目录名，不转内容
- 默认 smart 检测：名字已是合法 UTF-8 则跳过（`--nosmart` 强制）
- 默认 dry-run 只打印计划，`--notest` 才真正重命名

## 转换语义（内核核心公式）

```
新名 = to.GetString(from.GetBytes(旧名))
```

- `from` = 名字当前被误解的编码，`to` = 目标编码
- 双向通用：修复乱码（from=GBK → to=UTF-8）与制造乱码（from=UTF-8 → to=GBK）同一公式
- **失败判定**：克隆 from 置 `EncoderExceptionFallback`、克隆 to 置 `DecoderExceptionFallback`，捕获异常填 Reason（「原编码无法完整表示」「目标编码无法解析」「不支持的编码」）——异常回退等价 convmv test 模式，避免合法 '?' 误判
- **无变化判定**（convmv smart）：`from == to` 或名字为纯 ASCII → 直接返回原名
- 文件名转换**不走 BOM**（区别于 TextFileCodec 写文件的带 BOM 逻辑）

## 编码表（按 codePage）

UTF-8/65001、UTF-16 LE/1200、UTF-16 BE/1201、GBK/936、GB18030/54936、Big5/950、Latin-1/28591、Shift_JIS/932、EUC-JP/51932、EUC-KR/949、KOI8-R/20866、Windows-1251/1251、Windows-1252/1252、ISO-8859-2/28592

依赖 `TextFileCodec.cs` 已注册的 `CodePagesEncodingProvider`（L41-59，当前为私有，需新增 public 入口复用）。

## 新建文件

### 1. `src\TabTaskExplorer.Kernel\Services\FileNameEncodingConverter.cs`

内核纯字符串逻辑（跨平台，无 IO），代码组织参照 `BatchRenamePlanner.cs`（L5-74）：

- 模型：`EncodingChoice`（CodePage/Name）、`EncodeConvertEntry`（OldPath/NewName/Reason）
- `GetSupportedEncodings()`：返回上表编码列表
- `ConvertName(name, fromPage, toPage)`：实现核心公式 + 失败/无变化判定
- `BuildPlan(provider, paths, recursive, fromPage, toPage)`：收集路径（递归时深度遍历全部后代）→ 逐个 ConvertName → 返回 `List<EncodeConvertEntry>`

### 2. `src\TabTaskExplorer.App\Views\EncodeConvertDialog.axaml` + `.axaml.cs`

仿 `BatchRenameDialog.axaml(.cs)`（L3-49 / L28-90）结构：

- 入参：勾选的路径列表 `List<string> paths`
- 控件：源编码/目标编码下拉（绑定 GetSupportedEncodings）、递归 CheckBox、预览列表（旧路径/新名/原因）、执行/取消按钮
- 属性：`EncodeConvertPlan`（返回给调用方）
- `RebuildPreview()`：调内核 BuildPlan 刷新预览
- 执行 → `Close(true)`；取消 → `Close(false)`

### 3. `src\TabTaskExplorer.Tests\FileNameEncodingConverterTests.cs`

参照 `BatchRenamePlannerTests.cs`（L7-57）：
