# 复制/剪切与系统剪贴板互通 + 任意位置粘贴

## Context（背景）

当前程序的复制/剪切只写入内部剪贴板状态（`MainWindowViewModel` 的 `clipboardPaths` / `clipboardIsCut` 字段），不进系统剪贴板，因此：

- 在本程序复制的文件，无法到资源管理器等外部程序粘贴；
- 在资源管理器复制的文件，也无法在本程序内粘贴；
- 粘贴入口只有工具栏「粘贴」按钮与文件列表空白处右键两处，无法直接粘贴到指定的文件夹/导航项/标签。

用户要求：**复制、剪切与系统的复制到/剪切行为一致（双向互通），并可在任意位置粘贴**。经确认范围：

1. 双向互通：本程序复制/剪切 → 外部程序可粘贴（剪切=移动）；外部程序复制 → 本程序任意目录可粘贴（剪切同样按移动）。
2. 粘贴入口扩展：右键文件夹条目粘贴进该文件夹、导航栏（快捷访问/此电脑分组）、磁盘视图行、顶部标签页右键菜单；文件列表空白处与工具栏入口保留。

不改动网页客户端的独立剪贴板（浏览器无法访问系统文件剪贴板），仅同步网页端目录行「粘贴到该文件夹」入口。

## 关键已查明事实

- Avalonia 12.1.4 `IClipboard`：`SetDataAsync(IAsyncDataTransfer)` / `TryGetDataAsync()` / `FlushAsync()`；扩展 `TryGetFilesAsync()`、`SetFilesAsync()`。`DataFormat.File` 在 Windows 映射 CF_HDROP（Linux=text/uri-list），写入后资源管理器可粘贴，读取可取回外部文件列表。
- 自定义格式：`DataFormat.CreateBytesPlatformFormat("Preferred DropEffect")` 可读写 Windows 的剪切标记（DWORD=2 表示移动）；`DataFormat.CreateStringApplicationFormat("tabtaskexplorer-cut")` 用于跨进程自标记（含压缩包虚拟路径）。
- `SetFilesAsync`/`SetTextAsync` 会清空剪贴板 → 必须用**一次** `SetDataAsync` 组装全部格式；写完必须 `FlushAsync()`。
- 现有可复用能力：
  - 落地入口 `MainWindowViewModel.TransferPathsToDirectory`（src/TabTaskExplorer.App/ViewModels/MainWindowViewModel.cs#L1038）与 `ResolvePasteProvider`（#L1077，压缩包内/外解析）——签名不变，粘贴流程直接复用。
  - 系统剪贴板文本写入先例 `OnCopyVariantClick`（src/TabTaskExplorer.App/Views/MainWindow.axaml.cs#L1610-1616）。
  - 路径→存储项先例 `TryCreateStorageItem`/`CreateFileUri`（src/TabTaskExplorer.App/Views/FileListPanel.axaml.cs#L561-589）。
  - 服务注册先例 `ISystemContextMenuService`（src/TabTaskExplorer.App/CompositionRoot.cs）。
- 分层与跨平台硬约束：内核层放跨平台抽象与纯逻辑，应用层忽略平台差异，**三平台界面与功能完全一致**（不写空实现，Linux/macOS 走同一套 Avalonia API）。

## 改动清单

### 1. 内核层（新增，跨平台纯逻辑，不依赖 Avalonia）

- 新建 `src/TabTaskExplorer.Kernel/Abstractions/ISystemClipboardService.cs`
  - `bool IsSupported { get; }`
  - `Task WriteAsync(IReadOnlyList<string> paths, bool isCut)`（写系统剪贴板：真实磁盘路径写 File 格式 + 我方状态格式；压缩包虚拟路径只进状态格式）
  - `Task<ClipboardContent> ReadAsync()`（读系统剪贴板：文件列表 + 我方状态格式 + 系统剪切标记）
- 新建 `src/TabTaskExplorer.Kernel/Models/ClipboardContent.cs`：`HasTransfer`（剪贴板是否有数据）、`StatePaths`/`StateIsCut`（我方状态格式，含虚拟路径）、`SystemFiles`（外部文件路径列表）、`SystemCutIndicated`（系统剪切标记）。
- 新建 `src/TabTaskExplorer.Kernel/Services/ClipboardPastePolicy.cs`：纯函数 `Decide(ClipboardContent? content, IReadOnlyList<string>? internalPaths, bool internalIsCut) → (paths, isCut, 结果分类)`，判定顺序：
  1. 状态格式存在 → 用其路径与剪切标记（我方复制/剪切，含压缩包虚拟路径，视为真值）；
  2. 无状态格式但 `SystemFiles` 非空 → 外部文件 + 系统剪切标记（Windows Preferred DropEffect=2 / Linux `x-special/gnome-copied-files` 的 `cut` 前缀 / `application/x-kde-cutselection`；macOS 无文件剪切语义 → 一律复制）；
  3. 剪贴板有数据但既无文件也无状态（外部只复制了文本）→ 分类「无可粘贴的文件」；
  4. 剪贴板无数据 → 回退内部 `clipboardPaths`/`clipboardIsCut`；内部也为空 → 分类「剪贴板为空」。

### 2. 应用层（Avalonia 实现 + 注册）

- 新建 `src/TabTaskExplorer.App/Services/AvaloniaSystemClipboardService.cs`（三平台同一实现）：
  - 写：`DataTransfer` 一次组装——真实路径逐条 `DataTransferItem.CreateFile(storageItem)`（经 `IStorageProvider.TryGetFileFromPathAsync`）+ 状态格式 `tabtaskexplorer-cut`（"1|路径列表"，含虚拟路径）+ Windows 分支 `Preferred DropEffect`={2,0,0,0}；`SetDataAsync` 后 `FlushAsync()`。
  - 读：`TryGetDataAsync()` 一次取回 → 解析状态格式 → `TryGetFilesAsync()`（`TryGetLocalPath` 取真实路径）→ 解析系统剪切标记。
  - 线程：所有调用 `Dispatcher.UIThread.InvokeAsync`；剪贴板经 `Application.Current.ApplicationLifetime` 主窗口解析 TopLevel；全部 try/catch + `UiLogger`（失败记日志并回退内部剪贴板）。
- `src/TabTaskExplorer.App/CompositionRoot.cs`：`services.AddSingleton<ISystemClipboardService, AvaloniaSystemClipboardService>();`（不按平台分支）。

### 3. 复制/剪切写入与粘贴流程

- `src/TabTaskExplorer.App/ViewModels/MainWindowViewModel.cs`：

## 风险与规避

- **只用一次 `SetDataAsync`** 组装全部格式（`SetFilesAsync`/`SetTextAsync` 会清空剪贴板）；写后 `FlushAsync()`，否则程序退出后外部无法粘贴。
- 拖放落地仍走 `TransferPathsToDirectory` 原签名，`FileDropPolicy`、`ResolvePasteProvider` 原样复用，不受影响。
- `OnSystemMenuOpening`/`OnBackgroundMenuOpening` 的 `systemMenuHost.Items.Clear()` 只清占位子菜单，新增「粘贴」项带独立 Tag（`MenuPasteToFolder`）不冲突。
- WebWorkspace 独立剪贴板与 `paste` 动作返回值语义保持不变。
- 所有剪贴板读写 try/catch + `UiLogger` 中文日志（含失败与提前 return 分支），异常时回退内部剪贴板，不阻断粘贴。
