# 文件 / 文件夹拖拽移动与复制 实施方案

## 一、背景与目标（Context）

README 路线图中的待办项「鼠标拖拽移动 / 复制文件」至今未实现：全仓库搜索 `DragDrop / AllowDrop / DataObject` 零命中，目前只有标签条的一套手写指针拖拽（排序 + 拖出成新窗口）。用户要求「文件、文件夹要可以拖动」，并确认要覆盖全部场景：列表内互拖、拖到左侧导航/书签/地址栏、拖到标签条、拖出到 Windows 资源管理器与桌面等外部程序、以及从外部程序拖入本程序。参考实现沿用仓库根目录的 `tabx-snapshot`（TabX Explorer 的 rea 分析，已确认其走 `DoDragDrop / RegisterDragDrop / DragQueryFileW / CF_HDROP`，仅作交互参考，不需深挖）。

完成后：用户可像在 Windows 资源管理器中一样，用鼠标直接拖动文件与文件夹完成移动 / 复制，并与系统资源管理器双向互拖。

## 二、交互语义（统一规则，三端一致，无平台分支）

| 落点 | 行为 / 目标目录 | 拒绝（`e.Effects = None`） |
| --- | --- | --- |
| 列表空白处 | 移入当前标签 `CurrentPath` | `CurrentPath` 为空（此电脑根视图） |
| 文件夹行 | 移入该行 `row.FullPath` | 目标是源本身或源的子目录、源与目标同目录、本地目标目录不存在 |
| 文件行 | 拒绝（非容器不接收） | 全部 |
| 左侧导航（PinnedNavList / PcNavList）、书签项 | 移入该项 `QuickAccessItem.Path` | 路径为空、`Directory.Exists` 为假（含文件书签、远程路径） |
| 地址栏（AddressBarBorder） | **导航**：文件夹 → 当前标签 `OpenPath(该文件夹)`；文件 → `OpenPath(其所在目录)`；**不做任何移动/复制** | 目标标签为压缩包 / 远程标签 |
| 标签条某标签 | **仅文件夹**：该标签 `OpenPath(被拖文件夹)`；文件拖到标签上拒绝 | 目标非 `FileTabViewModel`、目标或源为压缩包标签、源不是本机条目 |
| 拖出本程序 | 交给系统 OLE（资源管理器自行套用 Ctrl/Shift），本程序不重复执行 | 源不是本机条目（远程 / 压缩包） |

**效果规则（全平台统一）**：`Path.GetPathRoot(源) == Path.GetPathRoot(目标)` → 移动，跨卷 → 复制；`Ctrl` 强制复制，`Shift` 强制移动（Ctrl 优先）。从外部程序拖入沿用同一规则。

**拖拽载荷**：进程内自定义格式 `FileDragPayload{ List<string> Paths; }`（区分「本程序发起」与「外部拖入」，并携带源标签信息）+ 每个本机路径一个 `DataTransferItem.CreateFile(IStorageItem)`（供系统 / 外部程序消费，Windows 侧由 Avalonia.Win32 转成 CF_HDROP）。远程条目只带进程内格式，不带文件项。

**参与范围（按 `tab.FileSystemProvider` 类型收口）**：

- `ArchiveFileSystemProvider`（压缩包虚拟标签）→ 发起与接收全部拒绝；
- `DefaultFileSystemProvider`（含 `WindowsFileSystemProvider` 等三端本机实现）→ 全场景可用；
- `SftpFileSystemProvider` / `FtpFileSystemProvider` → 仅允许**同一标签内部**拖放（空白处 / 文件夹行，直接用 provider 的 Copy/Move），拒绝拖出系统与拖到导航 / 书签 / 地址栏 / 其他标签。

## 三、关键技术确认（已核实，Avalonia 12.1.4）

- 拖出：`Avalonia.Input.DragDrop.DoDragDropAsync(PointerPressedEventArgs, IDataTransfer, DragDropEffects)`，在 `PointerPressed` 中调用并存下 `Task`（Avalonia 官方惯用法；OLE 自带拖拽阈值，普通点击不受影响）。返回值即目标实际应用的效果。
- 接收：`DragDrop.AllowDropProperty` 为 `inherits: true`，因此在 `MainWindow` 上设 `DragDrop.AllowDrop="True"` 即可让全窗口可接收；`DragEnter/DragOver/DragLeave/Drop` 均为冒泡路由事件，用 `DragDrop.Add*Handler(Interactive, EventHandler<DragEventArgs>)` 挂在窗口上，靠 `e.Handled` 与列表面板分区。
- `DragEventArgs`：`DataTransfer`（只读）、`Effects`（目标读写，设置将执行的效果）、`KeyModifiers`、`GetPosition(...)`。
- 读取拖入内容：扩展方法 `e.DataTransfer.TryGetFiles()` / `TryGetValue<T>(format)`；文件项取本地路径用 `TryGetLocalPath()`。
- 构造拖出内容：`TopLevel.GetTopLevel(ctrl).StorageProvider.TryGetFileFromPathAsync / TryGetFolderFromPathAsync(Uri)` → `DataTransferItem.CreateFile(IStorageItem)`。
- 进程内格式：`DataFormat.CreateInProcessFormat<FileDragPayload>("tabtaskexplorer-file-drag")`。

## 六、风险与冲突点

- **双击 / 勾选 / 右键菜单**：拖拽只在按下后位移超阈值才启动；按在勾选框上不发起拖拽；阈值前不拦截事件，既有交互零改动。
- **标签条拖动排序（MainWindow.axaml.cs L574-L800）**：拖拽期间指针事件由 OLE 接管，两套机制（指针拖拽 vs 系统拖放）互不干扰；标签条只注册 DragOver/Drop。
- **重复执行**：内部拖放由本程序 Drop 直接执行并置 `dropHandled`，`DoDragDropAsync` 返回后据此跳过二次处理。
- **同步 Copy/Move 阻塞 UI 线程**：与现状粘贴一致，本期不改（避免扩大改动面）。
- **三端一致**：只用 Avalonia 拖放 API，不写 `OperatingSystem.*` 分支；非 Windows 的拖出表现需实机验证，保证等价有效（不允许空实现）。
- 源码保持 UTF-8 BOM（build.bat 第 0 步有编码自愈兜底）。

## 七、验证方案

1. 构建：`stop.bat` → `build.bat` → 产物 `output\TabTaskExplorer.exe`。
2. 单测：`dotnet test TabTaskExplorer.sln` —— 新增 `FileDropPolicyTests` 全绿，既有用例无回归。
3. 桌面手工验证（拖拽是桌面端能力，只能在桌面端验证；逐项核对 UiLogger 中的中文日志要素）：
   - 列表内拖到文件夹行 / 空白处；同目录与「拖进自己的子目录」显示禁止且不执行；
   - `Ctrl` 复制、`Shift` 移动、同盘默认移动、跨盘默认复制；
   - 勾选多项后整体拖放；未勾选时只拖被按的行；
   - 拖到左侧导航、书签项 → 移入该目录；拖到地址栏 → 导航不移动；拖到标签条的文件夹标签 → 该标签导航，文件 → 禁止；
   - 拖出到桌面 / 资源管理器 / 其他程序；从资源管理器与桌面拖入列表；
   - 压缩包标签与远程标签的参与范围符合第二节；双击、右键菜单、勾选、标签拖动排序全部未受影响。
4. 浏览器镜像 `http://127.0.0.1:15919/`：仅回归确认列表勾选 / 右键 / 复制粘贴未被破坏（网页端无系统拖拽，不作为拖拽验证点）。
5. 日志检查：`UiLogger` 无新增错误，拖放相关日志包含源路径、目标目录、修饰键、效果与成功 / 失败条数。

## 八、本期不做

- 远程（SFTP/FTP）条目与系统之间的互拖（需走传输队列，属另一条线）；
- 压缩包虚拟目录的拖入拖出；
- 拖放的进度条与同名冲突对话框（沿用现有「成功 n 失败 m」提示，与粘贴一致）。
