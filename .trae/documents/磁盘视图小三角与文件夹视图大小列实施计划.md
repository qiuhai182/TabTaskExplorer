# 磁盘视图小三角点击 + 文件夹视图目录大小回填 实施计划

## 一、背景（Context）

两项需求（已通过三轮澄清锁定边界）：

1. **小三角与文件名点击等效**：网页端磁盘视图行首的展开箭头（`span.ico`，▸/▾）当前没有点击事件，只有文件名可点击展开/折叠。要求箭头点击效果与文件名完全一致。
2. **磁盘视图 / 文件夹视图"二合一"**：澄清结论为——
   - 形态：**只加大小列**（文件夹视图仅补上目录行的"大小"显示，不做树形展开合并）；
   - 入口：**两标签并存、文件夹加大小列**（磁盘视图标签保持现状完全不动；普通文件标签的"大小"列对目录行惰性回填统计值）。

现状：文件夹视图的"大小"列在双端 UI 都已存在（桌面 [FileListPanel.axaml](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/Views/FileListPanel.axaml) 已绑定 `SizeText`，网页端 renderTable 已渲染 `row.size`），唯独缺少目录行的数据来源——`FileRow.FromEntry` 只给文件设 `SizeText`，目录行恒为空。因此核心工作是**后端回填**，复用上一阶段已验证的 `DiskScanService.ComputeSizeShared` 单飞 + 快照机制。

**d) 回填批次**（新增字段 + 嵌套私有类，仿 DiskViewPanelViewModel.BackfillRequest 模式，不用 lambda）：

- 字段：`private CancellationTokenSource? sizeBackfillCancellation;`
- `LoadCore` 内（L685 `fetchGeneration = ++loadGeneration;` 之前）调用 `this.CancelSizeBackfill();` ——切路径/刷新即取消上一批。
- 新增私有方法：

```csharp
/// <summary>取消进行中的目录大小回填批次。</summary>
private void CancelSizeBackfill() { /* 取消并释放 sizeBackfillCancellation，置 null */ }

/// <summary>为可见目录行启动大小回填：单飞共享计算，同路径多视图只实际扫描一次。</summary>
private void StartSizeBackfill()
{
    if (this.scanService == null) return;                 // 远程标签不回填
    if (string.IsNullOrEmpty(this.currentPath)) return;   // 此电脑视图不回填（见决策 D2）
    List<FileRow> targets = 可见目录行（IsDirectory && string.IsNullOrEmpty(SizeText)）;
    if (targets.Count == 0) return;
    this.CancelSizeBackfill();
    CancellationTokenSource source = new CancellationTokenSource();
    this.sizeBackfillCancellation = source;
    int generation = this.loadGeneration;
    SizeBackfillBatch batch = new SizeBackfillBatch(this, targets, generation, source.Token);
    UiLogger.Log("文件标签", "开始目录大小回填：路径=" + this.currentPath
        + " 目录行数=" + targets.Count);
    Task.Run(batch.Execute);
}
```

- 嵌套类 `SizeBackfillBatch`（参照 DiskScanService.ComputeRun 的 owner 持有 + 方法组风格）：
  - 字段：`owner`（FileTabViewModel）、`rows`、`generation`、`token`、成功/失败计数。
  - `Execute()`：`Parallel.ForEach(rows, options, this.ComputeOne)`，`options = new ParallelOptions { MaxDegreeOfParallelism = Environment.ProcessorCount, CancellationToken = token }`；结束后 `Dispatcher.UIThread.Post(this.OnBatchFinished)`（携带计数字段）。
  - `ComputeOne(FileRow row)`：`long sizeBytes = this.owner.scanService!.ComputeSizeShared(row.FullPath, this.token);` → `Dispatcher.UIThread.Post(delegate { this.ApplyOne(row, sizeBytes); })`；`OperationCanceledException` 直接抛出终止；其他异常记日志（纯中文，含完整路径）。
  - `ApplyOne`：分代校验（`generation != owner.loadGeneration` 则丢弃）→ `row.UpdateSize(sizeBytes)`；若 `owner.sortField == "Size"` 则 `owner.ApplyFilter()`（现有方法，会按比较器重排输出）。
  - `OnBatchFinished`：分代校验 → `owner.sizeBackfillCancellation = null` → `owner.scanService!.SaveSnapshot()`（持久化本批新增的目录统计，下次启动/其他视图直接复用）→ 完成日志（路径、成功数、失败数）。
- 启动点：`ApplyFetchedRows`（L736 `ApplyFilter()` 之后、L738 空目录判断之前）调用 `this.StartSizeBackfill();`

**e) 关闭钩子**：新增 `public void Close()` → `CancelSizeBackfill()`（供标签关闭时停止回填、释放单飞订阅者）。

## 四、假设与决策（Assumptions & Decisions）

- **D1 箭头样式用内联 `cursor:pointer`**：只作用于磁盘视图目录行的箭头，不改全局 `.ico` 规则（避免波及文件行空占位与导航栏图标）。
- **D2 此电脑视图的驱动器行不回填**：`currentPath` 为空时整批跳过。理由：驱动器容量信息磁盘视图已提供；对 `C:\` 做整盘递归统计开销大，违背"最小资源占用"约束。文件夹视图（真实目录）是本需求目标场景。
- **D3 只回填当前可见目录行**：与磁盘视图同策略（仅统计展开层/可见项），避免大目录数千子目录一次性全量统计。
- **D4 回填结果持久化**：批次完成调 `SaveSnapshot()`，与磁盘视图 ApplyBackfill 行为一致，保证"快照多视图复用"。
- **D5 行属性更新一律经 `Dispatcher.UIThread.Post`**：后台计算线程不直接触碰绑定属性。
- **D6 取消语义**：切路径/刷新/关闭标签 → 取消本批订阅者（`ComputeSizeShared` 的 subscriberToken 只让自己退出，不影响其他标签页/网页的同路径计算，全部订阅者退出才取消底层——上一阶段已验证）。
- **D7 代码风格**：无 lambda（方法组/匿名 delegate 形式的 `Dispatcher.UIThread.Post(delegate { ... })` 与项目现状一致）、显式类型、纯中文完整日志（不缩写参数名）。
