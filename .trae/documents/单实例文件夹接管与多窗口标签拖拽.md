# 桌面端单实例文件夹接管 + 多窗口标签拖拽 实施计划

## 一、背景与目标（Context）

用户需求（原话与澄清答复）：

1. 「桌面端，要新开页面，默认在既有旧窗口内打开新标签页。」——再次启动程序/系统唤起时，不再另起窗口，转发给既有实例开新标签。
2. 「同一个路径的标签页，新开这个路径时，如果匹配到已经打开过，则自动切换到既有标签页，不再重复打开新的标签页。」
3. 「接管……功能未生效」→ 澄清：「只接管默认资源管理器程序的唤起。如微信里的：在文件夹中显示」「不是浏览器接管，是文件夹接管。」
4. 澄清答复：「单实例转发，标签页可以拖动顺序，可以拖动脱离原窗口独立为新窗口。禁止桌面端多实例，但允许多窗口。」
5. 「可以手动将多个标签页打开同一个路径。但系统接口唤起某个路径，由本程序接管时，如果该路径已有标签页，则不开新的，而是跳转到这个标签页。」（手动打开不去重，系统唤起才去重跳转）
6. 「全部做。」（单实例 + 多窗口 + 拖动排序 + 拖出成新窗口 + 接管生效，一次性交付）

### 根因（已定位）

- [Program.cs](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/Program.cs) 的 `Main` 完全忽略 `args`，且无单实例互斥：系统按接管注册 `"exe" "%V"` 唤起时，另起一个全新进程/新窗口，路径参数被丢弃——这就是「接管功能未生效」的直接根因。
- [DefaultFileManagerManager.cs](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/Services/DefaultFileManagerManager.cs) 注册 HKCU `Software\Classes\Directory\shell` 默认动词 open，command = `"exe" "%V"`，注册本身已正确，问题在程序侧不消费参数。
- 标签条无路径复用逻辑：[MainWindowViewModel.cs](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/ViewModels/MainWindowViewModel.cs) `AddTab`/`CreateFileTab`（L286/L320）总是新建；`OpenInFileTab`（L1725）只在当前无文件标签时才新建。
- 无任何 Mutex/NamedPipe 代码；[App.axaml.cs](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/App.axaml.cs) L33-34 只创建唯一 `MainWindow`，`CurrentMainWindow`（L202-212）基于 `desktop.MainWindow` 单窗口假设。
- 标签条 [MainWindow.axaml](file:///d:/TabTaskExplorer/src/TabTaskExplorer.App/Views/MainWindow.axaml) L33-77 是水平 StackPanel 的 ListBox，仅有标题栏 `BeginMoveDrag` 窗口拖动（MainWindow.axaml.cs L160-215），无标签拖拽。

## 三、方案总览

```
系统唤起 "exe" "%V"
   → Program.Main: 尝试获取命名 Mutex
      ├─ 获取成功（首实例）→ 正常启动 Avalonia，启动时把 desktop.Args 中的路径交给「系统唤起打开」流程
      └─ 获取失败（已有实例）→ 命名管道把路径转发给既有实例（无路径则发聚焦命令）→ 退出
既有实例收到命令
   → 跨全部窗口按规范化路径查找文件标签
      ├─ 命中 → 激活所在窗口 + 选中该标签（去重跳转，不新建）
      └─ 未命中 → 在主（首个）窗口 AddTab 新建
手动操作（新建标签按钮、书签、地址栏、网页端）→ 保持现状，不去重
多窗口：
   App 维护窗口注册表 WindowRegistry（主窗口 + 拖出窗口）
   关闭最后一个窗口才走 CloseToTray / 退出逻辑
标签条：
   按住标签水平拖动 → Tabs.Move 实时排序
   拖出标签条范围释放 → DetachTab 移出原 VM → 新建窗口承载该标签
```

分层说明：全部改动位于 App 应用层（Avalonia UI + .NET 通用 API）。单实例用的 `Mutex`/`NamedPipeServerStream`/`NamedPipeClientStream` 是 .NET 跨平台 API，Windows/Linux/macOS 行为一致；窗口与标签交互由 Avalonia 跨平台实现，三端界面与功能完全一致。内核层零改动；`DefaultFileManagerManager` 维持仅 Windows 写注册表、其他平台静默跳过（注册表接管是 Windows 概念，与现状一致）。

## 四、实施步骤

### 步骤 1：单实例 + 命令行参数转发

**新建 `src/TabTaskExplorer.App/Services/SingleInstanceService.cs`**（应用层，纯 .NET 跨平台）：

- 常量：互斥名 `TabTaskExplorer_DesktopSingleInstance`，管道名 `TabTaskExplorer_CommandPipe`。
- `TryRunAsSecondary(string[] args)`：
  - 循环最多 10 次、间隔 500 毫秒：尝试用 `NamedPipeClientStream(".", 管道名, PipeDirection.InOut)` 连接并发送消息，成功即返回 true。
  - 消息协议（简单文本，路径不含换行）：有路径 → `"OPEN\n" + string.Join("\n", 规范化前的原始参数)`；无路径 → `"FOCUS"`；写入后读取一行应答（`"OK"`）确认。
  - 全部失败后尝试一次性抢占 Mutex：抢到则返回 false（降级为正常主实例启动，避免唤起请求丢失），抢不到返回 true（退出）。
- `AcquirePrimary()`：`new Mutex(true, 互斥名, out createdNew)`，createdNew 为 true 时把 Mutex 句柄存入静态字段保持到进程结束；否则返回 false。
- `StartServer(Action<string> onCommand)`：在后台任务里循环 `NamedPipeServerStream`（`PipeOptions.Asynchronous`，单实例）`WaitForConnection` → 读取全部文本 → `Dispatcher.UIThread.Post` 回 UI 线程执行 `onCommand(消息)` → 应答 `"OK"` → 断开重开，服务随进程存活。

**改 `Program.cs` 的 `Main`：**

```csharp
public static void Main(string[] args)
{
    if (SingleInstanceService.AcquirePrimary())
    {
        BuildAvaloniaApp().StartWithClassicDesktopLifetime(args);
        return;
    }
    // 已有实例：把路径转发给既有实例后退出；转发不成功且抢到互斥量则降级为正常启动
    if (!SingleInstanceService.TryRunAsSecondary(args))
    {
        BuildAvaloniaApp().StartWithClassicDesktopLifetime(args);
    }
}
```

### 步骤 2：既有实例接收命令（启动参数 + 管道消息统一处理）

**改 `App.axaml.cs`：**

- 新增统一入口 `HandleExternalCommand(string message)`（UI 线程执行）：
  - 以 `"\n"` 拆分，首行为命令字：`FOCUS` → `ShowMainWindow()` 并记日志「收到聚焦请求」；`OPEN` → 对后续每一行路径调用主 VM 的 `OpenPathFromSystem(path)`。
  - 每步用 `Services.UiLogger.Log("程序行为", ...)` 纯中文记录：来源=系统唤起转发/启动参数、原始路径。
- `OnFrameworkInitializationCompleted` 中、主窗口创建完成后：
  - `desktop.ShutdownMode = ShutdownMode.OnLastWindowClose;`（多窗口下最后一个窗口关闭才退出；CloseToTray 的 Cancel 逻辑不受影响）。
  - `SingleInstanceService.StartServer(HandleExternalCommand)`。
  - 处理首实例自身启动参数：遍历 `desktop.Args`，把存在的目录（文件则取其父目录）交给 `mainViewModel.OpenPathFromSystem(...)`；不存在的参数记日志跳过。
  - 订阅管道与启动参数时点均在主窗口 DataContext 就绪之后，保证打开标签可用。

### 步骤 3：路径规范化 + 系统唤起去重跳转

**改 `MainWindowViewModel.cs`：**

- 新增 `private static string NormalizePath(string path)`：`Path.GetFullPath`（失败则原样 trim）→ 去掉尾部分隔符（盘根 `C:\` 除外）→ 统一按 `StringComparison.OrdinalIgnoreCase` 比较用。
- 新增 `public void OpenPathFromSystem(string path)`（仅系统唤起/单实例转发/启动参数走这里）：
  1. 规范化目标路径；目录不存在但文件存在 → 取父目录；均不存在 → 记日志跳过。
  2. **跨全部窗口去重查找**：遍历 `WindowRegistry.GetAllWindows()` 每个窗口的 VM 的 `Tabs`，匹配 `FileTabViewModel` 且 `NormalizePath(CurrentPath)` 相等（且非压缩包虚拟标签——`FileSystemProvider is ArchiveFileSystemProvider` 不参与匹配）。
  3. 命中 → 该窗口 `Show()`/`WindowState = Normal`/`Activate()`，`vm.SelectedTab = 命中标签`，记日志「系统唤起路径命中既有标签：窗口=… 路径=…」，返回。
  4. 未命中 → 记日志「系统唤起路径未命中，在主窗口新建标签」→ 主窗口 VM（`WindowRegistry` 首个窗口的 VM）`AddTab(path)`。
- 手动路径（`AddTab`、`OpenInFileTab`、书签、地址栏、网页端）保持现状，不去重。

### 步骤 5：标签拖动排序 + 拖出成新窗口

**改 `MainWindow.axaml.cs`（代码后台实现，MainWindow.axaml 无需改动）：**

在构造里对 `TabStrip`（x:Name 已存在）注册带 `handledEventsToo` 的指针事件：

- `PointerPressed`：
  - 定位按下的 `ListBoxItem`（从 `e.Source` 向上找容器），其 DataContext 必须是 `Tabs` 中的标签；若 `e.Source` 位于关闭按钮（Button）内部或按下的是右键 → 不启动拖拽（保留右键菜单）。
  - 记录：按下坐标、被按标签、是否可能拖拽；此时不拦截（让 ListBox 正常选中）。
- `PointerMoved`（未按下忽略）：
  - 未达拖拽阈值（水平位移 < 6 像素）→ 忽略。
  - 进入拖拽态：实时计算插入位置——遍历已生成的标签容器，按容器水平中点与指针 X 比较得出目标序号；目标 ≠ 当前序号时执行 `vm.Tabs.Move(当前序号, 目标序号)`（复用既有 `ObservableCollection.Move`，与 `TogglePinTab` 同机制），并更新当前序号；拖拽期间 `e.Handled = true`。
  - 同时判定「脱出候选」：指针 Y 超出 `TabStrip`  bounds 上下各 12 像素，或指针 X 越出窗口左右边界 → 标记 `detachCandidate = true`（脱出态停止 Move 重排）。
- `PointerReleased`：
  - 若 `detachCandidate` → `vm.DetachTab(tab)` → `WindowRegistry.CreateSecondaryWindow(services, vm.Settings, 释放点坐标)` → `newVm.AttachTab(tab)`；记日志「标签拖出为新窗口：路径=… 源窗口剩余标签数=…」。
  - 否则若发生过重排 → 记日志「标签拖动排序：路径=… 起始序号=… 结束序号=…」。
  - 清空拖拽状态。
- 拖拽结束吞掉后续点击误触发（用 `suppressNextClick` 标志在下一次无位移的 Press 中放行）。

约束（保持简单）：

- 拖拽只作用于 `Tabs` 集合的顺序/归属，不触发任何标签 `Close/Dispose`。
- 被拖标签为当前选中标签时，`SelectedTab` 跟随 `Move` 自动保持（ObservableCollection.Move 会同步 ListBox 选中）。
- 拖出后源窗口即使 0 个标签也保持打开（与现有 `CloseTab` 清空后的行为一致）。

### 步骤 6：文件夹接管验证与兜底

- 注册逻辑（`DefaultFileManagerManager`）保持不动——注册的 `"exe" "%V"` 本就正确，生效前提（消费参数 + 单实例）由步骤 1-3 补齐。

## 五、关键决策与假设

1. **去重范围**：仅 `OpenPathFromSystem`（系统唤起/单实例转发/启动参数）去重；手动 `AddTab`/书签/地址栏/网页端不去重（用户明确）。
2. **去重匹配对象**：仅真实文件标签（`FileTabViewModel`、非压缩包虚拟标签），路径比较用 `GetFullPath` + 去尾分隔符 + `OrdinalIgnoreCase`；任务看板/磁盘视图/进程面板标签不参与。
3. **未命中时新建位置**：固定在主窗口（注册表首个窗口），保证「默认在既有旧窗口内打开新标签页」。
4. **多实例禁止、多窗口允许**：同进程多个 `MainWindow`，第二进程一律转发后退出（转发失败且拿到互斥量才降级启动，避免丢唤起请求）。
5. **CloseToTray 仅对最后一个窗口生效**；关闭非最后窗口直接真实关闭，会话保存取全窗口并集，不丢标签。
6. **设置共享**：拖出窗口与主窗口共享同一 `AppSettings` 实例，避免多份 Load/Save 互相覆盖。
7. **跨平台**：Mutex/NamedPipe/Avalonia 拖拽均为跨平台实现，三端界面与功能一致；注册表接管仍仅 Windows（现状保持，其他平台静默跳过）。
8. **简单直观**：拖拽用指针事件 + `ObservableCollection.Move`，不引入第三方拖拽库；事件订阅用 `new EventHandler(...)` 显式方法而非 lambda（符合用户代码风格偏好）；日志纯中文、参数写全称。
9. 新增/修改源文件保持 UTF-8 BOM（build.bat 第 0 步有编码自愈兜底）。
