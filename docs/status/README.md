# 任务状态看板约定

本目录的 [BOARD.md](BOARD.md) 由 `tools/status/Build-StatusBoard.ps1` 生成，不要手改。

## 1. 状态词表

只允许五个值，不许自造同义词：

| 状态 | 含义 | 什么时候可以用 |
| --- | --- | --- |
| 待构建 | 代码已落地，尚未编译或发布 | 有改动，但没有包含该改动的新产物 |
| 待实测 | 已构建，缺运行证据 | 有产物，但还没在浏览器或桌面实际验证 |
| 已实测通过 | 有运行证据 | 构建退出码 0、测试通过、诊断包生成，或浏览器/桌面实测有记录 |
| 阻塞 | 被外部条件卡住 | 主机不可达、认证被拒、依赖缺失、执行环境故障 |
| 等你决策 | 需要用户拍板 | 范围取舍、是否继续排查、是否接受现状 |

规则：没有运行证据不得写「已实测通过」；阻塞必须写明卡在谁或什么；不写「基本完成」「差不多」等模糊词。

## 2. 每份 progress 文档必须维护状态头

位置：第一行 `#` 标题之后，固定三行：

```text
状态：<五个词之一>
卡点：<一句话，写明卡在谁/什么；没有就写“无”>
下一步：<一句话>
```

每次改动或验证后，先更新状态头，再写正文；状态变化会由脚本写入 BOARD 的变更日志。

## 3. 汇报只发增量

- 只汇报状态变化、新的阻塞或决策项、以及新产生的验证证据；未变化的任务线不重复汇报。
- 每条一行：`时间 任务线：旧状态 → 新状态（原因）`。
- 详细内容写在对应的 progress 文档，汇报里给链接，不粘贴长文。
